## Purpose

This framework creates a repeatable path from technology interest to architecture decision.

## Evaluation Criteria

| Criterion | Questions |
| --- | --- |
| Capability Fit | Which capability does it support, and what problem does it solve? |
| Learning Value | What durable engineering knowledge will be gained by evaluating it? |
| Enterprise Adoption | Is it used in enterprise environments or likely to be acceptable there? |
| Community Health | Is the ecosystem active, documented, and responsive? |
| Maintenance | How difficult will upgrades, debugging, and operational ownership be? |
| Complexity | Does it reduce or introduce complexity? |
| Cost | What are licensing, infrastructure, usage, and maintenance costs? |
| Migration Risk | How reversible is the decision? What lock-in does it create? |
| Interview Value | Does it demonstrate credible enterprise AI engineering judgment? |
| Overall Recommendation | Adopt, Trial, Assess, or Hold. |

## Evaluation Output

Each evaluation should produce:

- Technology evaluation artifact.
- Evidence summary.
- Recommendation.
- Related capability impact.
- ADR proposal when the recommendation changes architecture.
